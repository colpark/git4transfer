# Item 3 — BLAST-to-MSA path and the frozen-coverage ceiling

The old `blast_search` and `mmseqs_search` returned hit IDs and statistics but **neither sequences nor aligned rows**. The subject's tool grant did not include file reading. Thus the model could not legally assemble a homolog MSA from the search result, despite the FASTA path in the prompt. This was a tool-surface gap; the previous three guided calls supplied only the query row.

The rebuilt classical server adds `blast_msa(sequence, reference_fasta, max_hits)`. It calls the same BLASTP search, resolves the hit IDs against that explicit FASTA, globally aligns each distinct full hit sequence to the exact query under the already-used BLOSUM62/gap convention, drops subject insertion columns, and returns `query`, `msa` (query first), depth and used IDs. The guided classical variant screen now chains this retrieval/alignment with the **unchanged** PSSM, conservation and BLOSUM calculations. The scorer still enforces its preregistered at-least-two-row, ≥80%-query-coverage rule. This is not a claim of a new general-purpose multiple-sequence alignment algorithm; it is a deterministic query-anchored input path. Its construction convention must be disclosed in any later scored use.

Controls through the actual MCP interface are in `surface_controls.json`. A small, independent, two-sequence fixture passed (`blast_msa` depth 2, PSSM and guided screen return values with resolving receipts). A malformed multi-character mutant failed. Crucially, **one-sequence conservation returned null/error**, as required; apparent conservation of a single query is no longer accepted as evidence. The negative control on the actual pilot item also failed as it should.

The actual item 2 reference FASTA is a deeper problem: it has 200 rows including the 177-aa exact query, but under the frozen 80% coverage rule **zero of its 199 other full sequences produce a qualifying query-anchored row**. The closest global alignment has 36 query-gap columns; ≤35 are allowed because 20% of 177 is 35.4. BLAST's top hits are mostly 126–145 aa and cover a shorter homologous domain. Thus `blast_msa` correctly returns null/error even with `max_hits=100`, and merely teaching the agent to pass an MSA cannot make PSSM/conservation valid on this item. We did **not** lower the coverage threshold, trim the task sequence, fabricate duplicate rows, substitute a different FASTA, or change the scorer. This item has no valid MSA-based classical score under the registered convention. Any later use requires an explicit panel decision on the data or convention; Stage 4 remains closed.
