# Stage 3g finding — zero-FM has multiple causes, not one failed model

14 September 2026 UTC. **Stage 4 remains closed.** No item was scored; no DMS label or evaluator was opened. The only subject invocations were one registered-7B echo, one 7B unguided cell, one 7B ESM-2-only probe, one 30B echo, and its single same-item cell; there were no further pilot cells.

1. **Harness repaired and verified.** Codex now resolves the local model catalog: the 7B and 30B echo traces have no fallback-metadata warning. The 7B's model-visible instructions are byte-identical before and after registration; Stage 3f already overrode context to 32K, so missing metadata alone was not a sufficient explanation. More serious: Stage 3f's record server accepted only Stage 4 output paths, leaving `submit_answer` **absent** from its tool grant. That deterministic no-submission defect is repaired, with positive/negative record controls. In the 7B unguided cell the record tool was visible, yet unused.
2. **Guided presentation was asymmetric.** The old model-visible list had all three atomic FM tools but only a named **classical** variant-screen composite. A matching ESM-2/ESM-IF1 guided composite has been added and passed positive/negative direct controls. No post-repair guided subject cell was run, so a clean guided-versus-unguided causal effect is **unknown**.
3. **7B can call ESM-2, but did not select it under load.** The one-tool 650M ESM-2 probe passed with one correct score and real receipt. The same item in the full unguided Arm 3 grant made **7/7 classical calls, zero FM calls and no submission** (34.69 s). The record channel and FM atoms were visible. The final message requested further user direction rather than satisfying the answer contract. This is a selection/output-contract failure under the crowded task, not ESM-2 schema incomprehension.
4. **30B retry is reachable but its cell is inconclusive.** The pinned Qwen3-30B-A3B Q4 model loaded with GPU placement, passed one real echo call and remained within reported thermal/memory conditions. Its first full-item response exhausted the **1,200-token per-response cap entirely in reasoning**, with `finish_reason: length`, empty visible answer and zero observable tool calls. Mark the cell **UNDEMONSTRATED**, not a 0%-tool model failure; no second cell or cap change was run.
5. **Classical MSA chain is incomplete.** BLAST and MMseqs return IDs/statistics, not sequences or alignments. No model-visible tool converts a hit or the supplied FASTA into the `msa` rows expected by PSSM/conservation. Stage 3f supplied a one-sequence list. Its duplicate BLAST call returned a cache hit with no new information; the trace does not explain why it repeated.

**Panel recommendation:** do not attribute zero-FM to subject quality, presentation, or metadata alone. Rule first on (a) the incomplete retrieval→MSA tool path and the now-changed Stage 4 frozen harness hashes, (b) whether to allocate a fresh, explicitly labeled 30B cell with a larger *harness* output cap, and (c) whether to test the repaired guided mode against unguided on a new non-scored item. No prompts, metrics, scoring thresholds or arm definitions were changed here. The modified shim/record-server hashes deliberately invalidate the old Stage 4 pilot freeze until the panel re-freezes infrastructure; we have not silently updated that manifest.
