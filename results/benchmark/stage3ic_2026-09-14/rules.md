# Stage 3i-c standing rules, panel amendment

14 September 2026. **A gate must measure the quantity it claims to protect, not a proxy for it.** This is the project's fifth proxy-gate correction. The earlier blanket prohibition on every native tool is replaced by the named-threat rule:

> NO NATIVE TOOL MAY PROVIDE A PATH TO COMPUTATION THE ARM GRANT EXCLUDES.

Shell, executable code/package installation and network fetch meet that bar. File editing and image viewing without an execution path do not. Keep the code-mode host up for MCP routing while denying nested shell and other executable/network capabilities. Test the property with an MCP-free ESM-2 bypass control and a shell must-fail control; a catalog alone is not the firewall.

Carry forward the accepted prior-grant disclosure verbatim wherever 7B/30B behavior is cited: "shim-filtered MCP-only at the model boundary, not an MCP-only Codex arm; Stage 3f additionally lacked the record server; the removed ChatGPT session's effect outside captured requests is unknown."

An asymmetric tool presentation remains a confound in frontier-versus-small comparisons. Receipt validity is not evidence relevance **or success**: inspect the result/error body and artifact, as the failed headerless-PDB DSSP probe demonstrated. A control assumed in place is not verified. Do not widen a definition to pass, score an interrupted run as zero, open labels before blinding, or describe unknowns as measured values. A served checkpoint is part of a tool's identity; a tool must measure the quantity the task scores on.
