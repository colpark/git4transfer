# Config/surface correction: 19 advertised functions to 18

14 September 2026. The seven-server Claude config still points to the same local `benchmark-mcp/server.py` and `pilot_record_server.py` processes used by the Codex B4 grant. The **physics server registration** was corrected before the Opus grant check: its `@mcp.tool(name="pyrosetta_ddg")` wrapper was removed from `make_physics`. No scored item, metric, prompt, model checkpoint, energy implementation, or other MCP function was changed. The new physics `list_tools()` returns exactly `dssp` and `openmm_snapshot_potential_delta`; the latter retains its corrected name and its structural-diagnostic-only description.

This was not merely a catalog-label quirk. Before correction, `server.py` advertised `pyrosetta_ddg` as callable. The underlying `physics.py:pyrosetta_ddg` **always raises**: `PyRosetta institutional license and runnable current-host aarch64 build not verified; no physics ddG substitute is authorized`. A direct unscored call on the existing 1UBQ fixture reproduced that exception. Thus the server advertised a capability that could not produce a ddG result. The blocked implementation remains in `physics.py` for the record but is no longer exposed by MCP.

The corrected [rescue_seven.json](rescue_seven.json) mounts **exactly seven** stdio servers on `spark-112b`/`192.168.100.10`. The record server's unchanged path allowlist requires its per-run artifacts under the already-permitted `stage4prep_2026-09-14/claude_b4_record_d`; those artifacts were copied to this stage for audit. No eighth server, HTTP relocation, or node-11 serving path was introduced. The model-side check, not this config file, established the final 18-function catalog.

The earlier Stage 4-prep hash set included `server.py`; this permitted tool-surface correction makes that historical freeze **stale again**. It must be explicitly superseded before any scored 146-item run. This control is unscored and does not re-register the cohort.
